## 1. 지침은 이미 있는데 코드가 아직 안 따라온 것

### 1.1 해요체가 보유세 화면에만 적용됐다 🚨

§3.1은 *"상황, 맥락을 불문하고"* 해요체를 요구한다. 그런데 §9의 적용 표는 조건 화면만
다루고 있어, **사이드바·검색·지도·포트폴리오가 사각지대로 남았다.**

| 파일 | 합쇼체 | 해요체 |
|---|---:|---:|
| `messages/sidebar.ts` | **37** | 2 |
| `messages/map.ts` | 3 | 3 |
| `messages/search.ts` | 3 | 1 |
| `messages/portfolio.ts` | 2 | 1 |
| `messages/holding-tax.ts` | 4 (= `cautions`, 의도됨) | 31 |

**의도된 4건을 뺀 45건이 미적용이다.** 앱 전체로 보면 합쇼체가 여전히 다수다.

사용자는 `검색 → 사이드바 → 보유세`를 한 흐름으로 지난다. **한 세션에서 문체가 두 번 바뀐다.**

### 1.2 긍정형이 사이드바에 미적용

§3.1: *"안 돼요, 없어요 (X) → ~하면 할 수 있어요 (O)"*

`messages/sidebar.ts` 한글 문구 76개 중 **24개(32%)가 부정 표현**이다.

```
'단지 정보를 불러오지 못했습니다.'
'동 목록 조회에서 정상 응답을 받지 못했습니다.'
'동·호 목록 원천 서비스에 연결할 수 없습니다.'
'선택한 동·호의 공시가격 자료가 없습니다.'
```

§3.1의 부정형 허용 예외(정책상 불가 / 사용자 선택 결과 / 민감정보 안심) 중
**어느 것에도 해당하지 않는다.** §3.4의 필수 3요소(상황·이유·**해결책**) 중 해결책이 없다.

특히 `'정상 응답을 받지 못했습니다'`는 §3.4-4가 지목한 실패 유형이다 — 내부 사정을
사용자 언어로 번역하지 않았다(*"알 수 없는 신분증"* 사례와 같은 형태).

**같은 파일에 정답이 이미 있다:**

> `'목록을 불러오지 못했습니다. 동·호를 알고 있다면 직접 입력해 조회할 수 있습니다.'`

뒤 절이 §3.4-3(스스로 해결할 방법)을 만족한다. **이 패턴을 24건에 확장하면 되는 문제고,
새 설계가 필요 없다.**

### 1.3 위급하지 않은데 경고색

§3.4-2: *"별로 위급한 상황이 아닌데 빨간색을 써서 실제보다 더 심각한 상황처럼 전달"*
§4.3: **"세액이 늘어난다고 빨간색을 쓰지 않는다."**

`.holding-overlay__cap-warning`이 `--color-warning` 노랑 테두리 + 배경을 쓴다
(`holding-tax-overlay.css:97-102`). 그런데 내용은 오류가 아니라 **계산 방법 안내**다 —
"2025년 자료가 없어 상한 미적용, 표시값은 상한선".

게다가 `HoldingTaxOverlay.tsx:201`에서 `role="note"`를 줬다.
**시맨틱은 note, 시각은 경고**로 어긋난다. 둘 중 하나로 맞춰야 한다.

### 1.4 면책이 3자리가 아니라 5자리에 있다

§5.1은 **세 자리**(결과 카드 안 / 입력 옆 / 하단 유의사항)를 규정한다.
현재 `HoldingTaxOverlay.tsx:190-249`는 **다섯 자리**다.

```
__model-note  →  __cap-warning  →  __prose-assumptions  →  __cautions
                                    (+ 결과 카드 안 disclaimer)
```

실측 분량 (결과 화면 상시 노출):

| 블록 | 분량 |
|---|---:|
| 가정·고지 카피 10종 | 539자 |
| `cautions` 4문단 | 278자 |
| 표 `비고` 열 25종 | 471자 |
| **합계** | **≈1,290자** |

**그리고 같은 사실을 반복한다:**

| 내용 | 횟수 | 키 |
|---|---:|---|
| 정부안이라 바뀔 수 있다 | 2 | `governmentBillNotice` / `cautions[1]` |
| 예측값이니 참고용 | 2 (거의 逐字) | `resultCardDisclaimer` / `cautions[2]` |
| 세부담상한 동일가격 모형 | 2 | `samePriceModelNotice` / `modeledCapAssumption` |
| 2025년 자료 없어 2026 상한 미적용 | **3** | `currentYearCapUnavailable` / `unavailableCapAssumption` / `basisCurrentYearBurdenCap` |

**817자 중 350~400자가 순수 중복이다.**

§5.1은 자리를 나누라 했지 같은 문장을 복제하라 하지 않았다. 지금 상태는
§1.4(*"위험은 설명이 아니라 설계로 통제한다"*)와 정면으로 어긋난다 — **면책이 4겹이면
아무도 안 읽고, 정작 중요한 "2026년 값은 상한선"이 나머지 3겹에 묻힌다.**

## 2. 지침이 아직 다루지 않은 영역 (문구가 아닌 것)

가이드는 **문구와 정보 구조**의 SSOT다. 아래는 그 범위 밖이라 규정이 없다.

### 2.1 카드가 너무 많다

`holding-tax-overlay.css`에 테두리/배경/반경을 가진 **면(surface) 정의가 15개**다.
화면당 실제 렌더링 개수:

**결과 화면 — 9개**
```
[neutral-50 배경]
 ├ .holding-assumptions              (헤더 카드)
 ├ .holding-result-summary           (흰 카드)
 │   └ article ×3                    (회색 카드 — 중첩 2단)
 ├ .holding-overlay__model-note      (회색)
 ├ .holding-overlay__cap-warning     (노랑)
 ├ .holding-overlay__prose-assumptions (흰 카드)
 └ .holding-tax-table-scroll         (테두리+그림자)
```

**조건 화면 — 13개, 중첩 3단** (물건 2건 기준)
```
.holding-conditions                   padding 24px
 ├ __missing   ├ __owner
 └ fieldset ×2                        padding 16px
     ├ __facts (회색)                 padding 12px
     └ __question ×3 (테두리)         padding 12px
```

**대가:**

- **가로** — 모바일에서 중첩 패딩이 누적된다.
  `content 12 + conditions 16 + fieldset 16 + question 12 = 56px` × 양쪽 = **112px**.
  §5.3(360px 폭)에서 **31%가 중첩 여백**이다. 데스크톱은 136px.
- **세로** — 결과 화면 최상위 카드 6개 × 상하 패딩만 288px.
  스크롤이 긴 주 원인이 텍스트가 아니라 껍데기다.
- **배경 3단 적층** — `neutral-50` → `neutral-0` → `neutral-100`.

**토스에서 카드는 "탭할 수 있는 하나의 대상" 또는 "독립된 하나의 개념"을 뜻한다.**
이 코드는 *의미 그룹마다* 박스를 쳤다. `__owner`도 박스, `__question` 하나하나도 박스.
그 결과 **박스가 아무 의미도 전달하지 못한다.**

§7-5(*"시니어는 막연히 스크롤하지 않는다"*)와 곱해지면 더 나쁘다 — 접히지 않은 카드
9개를 세로로 쌓으면 아래쪽은 없는 것과 같다.

제안: 카드로 남길 것은 **결과 요약 3장과 비교표**뿐. 나머지는 구분선·여백·타이포 위계로.
결과 9 → 4, 조건 13 → 3, 중첩 3단 → 1단.

### 2.2 강조 수단이 박스밖에 없다

2.1의 원인이다. 현재 시각 위계 자원이 빈약하다:

- 최대 폰트가 `--font-size-xl: 24px` — **결과 세액도 24px**
- 강조색이 `--color-accent: #173f5f` 하나 (채도 낮은 네이비)
- 아이콘·그래픽 0개 (`helpSymbol: '?'` 텍스트뿐)
- 앱 전체 트랜지션 1개 (`app.css:50`)

**"중요하다"를 표현할 방법이 박스 추가와 문단 추가밖에 없어서 계속 쌓였다.**
1.4의 면책 중복과 2.1의 카드 남발은 같은 뿌리다.

§4.4(절대금액 > 퍼센트)를 적용하려 해도 지금 타이포 스케일로는
`"320만 원 더 내요"`를 24px로밖에 못 쓴다.

### 2.3 결과 3장에 델타가 없다

`HoldingTaxResultSummary.tsx:26-38` — 2026/2027/2028 카드가 **완전히 같은 스타일**이고,
**증감액 자체가 화면에 없다.** 사용자가 세 숫자를 눈으로 뺀다.

이 제품의 존재 이유가 "현행 vs 정부안, 내 세금이 얼마나 바뀌나"인데
그 답이 화면에 없다. §4.4가 요구하는 형태다.

⚠️ 단, §4.3에 따라 **증가를 빨간색으로 칠하지 않는다.**

### 2.4 다크 모드 전무

`prefers-color-scheme` 검색 결과 **0건**. `tokens.css`에 다크 팔레트가 없다.
1차 자료(consumer-ux-guide)는 라이트/다크 양쪽 가시성 확보를 요구한다.

### 2.5 브레이크포인트 3종

`40rem(640px)` / `45rem(720px)` / `720px`가 섞여 있다. 같은 720px를 두 표기로 쓴다.
1차 자료는 논리 해상도를 **하나만** 고르라고 명시한다.

### 2.6 터치 타깃 미달

- `.tax-term-help__trigger` — **16 × 16px** (`holding-tax-overlay.css:472-483`)
- `.holding-overlay button` — padding 8/12px → 실측 약 37px

§4.2의 토스 실물이 15px 아이콘인 건 맞지만, **히트 영역**은 별개다.
현재는 아이콘과 히트 영역이 동일하다.

(`.complex-search__input`은 `min-height: 3rem` = 48px로 잘 잡혀 있다.)

## 3. 잘 맞는 것 — 바꾸지 말 것

- **`residencyQuestion: '이 집에 살고 계신가요?'`** — §3.1의 공식 예외
  (*"사용자의 상황을 추정할 때"*)에 정확히 해당. 화면 제목이라 §1.2 위반도 아니다.
- **CTA 라벨** — `'이 조건으로 계산'`, `'닫기'`, `'네/아니요'`. 버튼만 보고 다음 행동 예상 가능.
- **다이얼로그 왼쪽 버튼** — `TaxTermHelp`가 `'닫기'`. §3.1이 요구하는 그 규칙.
- **법정 용어 유지 + 병기** — `'1세대1주택 재산세 감면 특례'`를 풀지 않고,
  `basis*` 25종이 `'공시가격 × 내 지분'`처럼 옆에서 설명. §1.1과 §4.1 그대로다.
- **결과 카드 기준 표기** — `headlineBasis`가 숫자 아래 기준일·근거를 단다. §5.3 충족.
- **비교표 인라인 + `overflow-x`** — §4.1이 요구한 형태. 바텀시트를 쓰지 않았다.
- **`cautions` 격식체** — §5.2 결정대로.

## 4. 제안 — §9 확장 형태

성격이 달라 세 갈래다. **A가 위험이 가장 낮다** (문자열만 교체, 로직·구조 무관).

| # | 범위 | 대상 파일 | 근거 |
|---|---|---|---|
| **A** | 문체 해요체 통일 45건 · 부정형→긍정형 24건(해결책 포함) · 중복 면책 4쌍 제거(−400자) | `messages/**` | §3.1, §3.4, §5.1 |
| **B** | 카드 9→4 / 13→3 · 중첩 3단→1단 · 결과 델타 표기 · 타이포 스케일 확장 · `cap-warning` 경고색 제거 | `holding-tax-overlay.css`, `HoldingTaxOverlay.tsx`, `HoldingTaxResultSummary.tsx`, `tokens.css` | §1.4, §4.3, §4.4, §7-5 |
| **C** | 다크모드 토큰 · 브레이크포인트 단일화 · 히트 영역 44px | `tokens.css`, 각 `*.css` | 1차 자료 |

**B·C는 §9와 같은 파일을 건드린다.** §9 작업이 끝난 뒤에 착수하는 편이 안전하다.
A는 `messages/sidebar.ts`가 주 대상이라 §9와 겹치지 않는다.
