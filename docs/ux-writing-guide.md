## 1. 절대 하지 말 것

### 1.1 법정 용어를 쉬운 말로 바꾸지 않는다 🚨

토스증권이 **미수거래**를 **"외상구매"**로 개명했다가 **금융감독원 시정 요구**로 2025년 1월
원복했다. 사유: **"법령상 용어와 다른 표현을 사용하면 투자자가 오인할 가능성이 있다"**
(https://www.sedaily.com/article/13984748, https://ditoday.com/미수거래는-외상-옵션투자는-홀짝-게임토스의/)

토스의 "Zero Jargon" 목표에는 **한국 금융에서 법적 천장이 있다.**

```
❌  집 오래 갖고 있으면 깎아주는 돈
✅  장기보유특별공제 ⓘ   → "10년 이상 보유하면 세금을 최대 40% 깎아줘요"
```

**법정 용어를 라벨로 두고, 옆에 쉬운 설명을 붙인다.** 대체가 아니라 병기다.
대상: 종합부동산세 · 재산세 · 장기보유특별공제 · 조정대상지역 · 공정시장가액비율 · 과세표준.

### 1.2 버튼·목록 행에 질문형을 쓰지 않는다

토스가 **50대 이상 사용자 대면 조사**에서 찾은 실패다(토스 50+ 사용자 약 730만 명):

> 일부 시니어 사용자들은 **질문의 주체를 명확하게 이해하지 못하고 '나에게 질문한다'라고
> 문장 그대로 받아들여** 혼란스러워했어요
> — https://toss.tech/article/senior-usability-research

토스는 이걸 **TDS에 금지 안내문으로** 반영했다.

```
화면 제목    이 집에 살고 계신가요?      ← 토스가 말하는 것이 명확
버튼 / 행    거주 여부 확인하기          ← 질문형 금지
```

**부동산 세금은 토스 핵심층보다 사용자 나이대가 높다.** 우리에게 더 중요하다.

### 1.3 사용자 상황을 단정·추측하지 않는다

> 토스는 사용자를 속이지 않는 문구를 쓰기 위한 여러가지 원칙들이 있어요. 클릭을 유도하기
> 위해 과장하거나 불안을 자극하지 않고 … **사용자의 상황을 단정하거나 추측하는 표현**은
> 물론이고, 유행어나 특정 집단만 아는 은어도 지양해요.
> — https://toss.tech/article/Marketing_Writing

세액 추정기에 직접 걸린다. `"세금 폭탄을 피하세요"` 같은 문구는 쓰지 않는다.

### 1.4 위험은 설명이 아니라 설계로 통제한다

토스증권 옵션 사례에 대한 외부 비평(3자 블로그):

> 위험에 대한 설명이 아무리 길어도, '5% 상승 → 214% 수익' 같은 **시각적 피드백이 주는
> 쾌감은 그 모든 텍스트를 무력화**시킵니다. **위험은 설명으로 막는 것이 아니라, 설계로
> 제어해야 하는 영역**
> — https://brunch.co.kr/@daisyuxui/64

우리 화면도 `"개편안 적용 시 3.7배"` 같은 값을 띄우게 된다. 면책 문구 길이로 해결되지 않는다.
**기준일·산출근거를 숫자와 같은 시각 위계에 둔다.**

## 2. 질문 설계

### 2.1 3초 테스트

> "저녁 뭐 먹을래?" vs "저녁에 피자 먹을까?" — 어떤 질문에 더 대답하기 쉬운가요?
> **3초 안에 답이 안 나오면 어려운 질문이에요.**
> — https://toss.tech/article/insurance-claim-process

토스 보험청구의 실제 개선:

| Before | After |
|---|---|
| 전문가 도움받을까요, 직접 할래요? | **서류 있나요?** |

**과정을 고르게 하지 말고, 사용자가 이미 아는 사실을 묻는다.**
(이탈 감소 수치를 같은 글이 50%와 60%로 다르게 적는다 — 방향만 취한다.)

우리에게 옮기면:

```
❌  거주 여부  [비거주 주택 ▾]
✅  이 집에 살고 계신가요?     ● 네    ○ 아니요
```

### 2.2 1 thing for 1 page — 깨도 되는 조건이 있다

> 토스에는 **1 thing for 1 page** 라는 제품 원칙이 있는데요. 하나의 화면에서 하나의 액션만
> 시키라는 내용이예요.
> — https://toss.tech/article/toss-signup-process

같은 글에서 회원가입은 이 원칙을 **깬다.** 조건은 명시돼 있다 —
*"주민번호, 통신사, 핸드폰번호 모두 **일정한 데이터 형식**이었기에 이런 솔루션이 가능했어요."*

**판단이 필요한 질문은 한 화면에 하나.** 형식이 고정된 짧은 입력만 묶는다.
우리 기준: `거주 여부`·`이사 사유`는 판단 → 각자 한 화면. `나이`·`보유기간` 숫자는 묶어도 된다.

### 2.3 답을 모르는 사용자 다루기

토스의 네 가지 방법:

1. **정의 대신 그림.** 보험청구에서 "더 알아보기" 페이지를 검토했다가 버리고
   진료비 영수증·약제비 영수증의 대표 이미지를 넣었다
2. **이미 가진 데이터로 선택지를 줄인다.** 연동된 보험사만 노출 → 이탈률 개선
3. **못 답하는 사람은 다른 퍼널로 보낸다** — 억지로 통과시키지 않는다
4. **판단을 사용자에게 넘길 때는 경어로 정중히 묻는다** — 아래 §3.1의 공식 예외

### 2.4 입력 화면 비용 기준 — 우리는 지금 전부 위반

> - **질문이 3, 4개 이상**이면 사용자는 지치기 시작해요
> - **5초 내에 답변하기 어려운 질문**이라면 사용자가 고민하게 만들어요
> - 민감한 질문을 받았을 때 거부감이 커질 수 있어요
> — https://toss.tech/article/value-first-cost-later

현재 우리 조건 화면은 물건 1채에 6개, 3채면 16개다. **셋 다 위반이다.**

## 3. 문구 규칙

출처: https://developers-apps-in-toss.toss.im/design/consumer-ux-guide.md (1차 자료, 현행)

### 3.1 기본형

| 규칙 | 내용 |
|---|---|
| **해요체** | 모든 문구. *"상황, 맥락을 불문하고"* |
| **능동형** | 됐어요 → 했어요 |
| **긍정형** | "안 돼요, 없어요 (X) → ~하면 할 수 있어요 (O)" |
| **캐주얼한 경어** | `~시겠어요?` `~께` 금지. `계시다`→`있다` |
| **명사+명사 금지** | 한자어를 동사로 풀어쓴다 |
| **다이얼로그 왼쪽 버튼** | 항상 **[닫기]**. *"**취소**는 사용자가 하고 있는 작업이 취소된다고 오해할 수 있어 쓰지 않아요"* |

**공식 예외 — 경어를 써도 되는 때** (우리에게 정확히 해당):

> **사용자의 상황을 추정할 때** — 토스에 명확한 정보가 없어서 사용자에게 직접 판단하게
> 해야 할 때 '경어'로 정중하게 질문할 수 있어요.

→ `"실제로 거주하셨나요?"` 처럼 우리가 알 수 없는 사실을 물을 때 허용된다.

### 3.2 질문 문장을 다시 쓰는 요령

> 사용자의 정보를 받는 질문에서 기계적으로 '~시'를 뺐을 때 문장이 어색할 수 있어요.
> **파악하고 싶은 정보를 '주어'로 써서 문장을 새롭게 써보세요.**

```
❌  언제 취득하셨어요?
✅  취득일이 언제인가요?
```

### 3.3 문장 길이·용어

- **길이 수치 기준은 공개된 게 없다.** 공개된 건 원칙뿐 —
  *"한 문장 안에는 가능하면 **하나의 메시지만** 담아서"*, 그리고
  *"이 원칙의 핵심은 Easy to **read**가 아니라 **speak**"* — **소리 내어 읽어본다**
- **잡초 뽑기**: "앞으로" 같은 *"넣어도 그만, 빠져도 그만인 단어"*를 지운다
- 용어는 §1.1의 제약 안에서 최대한 쉽게

### 3.4 오류 메시지 — 6원칙

출처: https://toss.tech/article/how-to-write-error-message

필수 구성: **상황 설명 / 이유 / 해결책**

1. **최고의 에러는 발생하지 않는 것** — 에러가 날 수 없게 UX를 고친다
2. **적절한 컴포넌트** — *"토스트는 3~5초 사이에 사라지는 컴포넌트인데, 너무 많은 내용이
   담겨있죠"*, *"별로 위급한 상황이 아닌데 빨간색을 써서 실제보다 더 심각한 상황처럼"*
3. **스스로 해결할 방법 알려주기**
4. **사용자 입장의 언어** — 만료된 신분증에 *"**알 수 없는** 신분증"*이라 쓴 실패 사례
5. **쉽게 해결하게 돕기** — "고객센터로 문의해주세요" 대신 버튼을 놓는다
6. **부정적 감정 최소화** — *"'~해야 해요'라고 강요하는 말투보다, '~할 수 있어요'라고 권유"*

가장 좋은 예:
```
❌  비밀번호를 틀렸어요
✅  김토스님의 정보가 아니에요
```

## 4. 결과와 숫자

### 4.1 근거 공개는 **인라인 펼치기**

토스는 대출이자·DSR 계산기를 공개 운영한다
(https://toss.im/tossfeed/calculator, https://toss.im/tossfeed/calculator/dsr).

```
총 대출이자   12,345,678원   [펼쳐보기]
                              ↓ 회차별 상환표 전체 (회차 | 총 상환액 | 원금·이자 | 날짜)

현재 DSR      32.45%   [DSR 금리 계산 상세보기]
                              ↓ 계좌별 "7% (4% + 스트레스 금리 3%p)"
```

**산식을 화면에 그대로 인쇄한다.** `7% (4% + 스트레스 금리 3%p)` — 우리 `비고` 열과 같은 발상.
길어지는 파생 표는 **바텀시트가 아니라 인라인 펼치기**다. 표 컨테이너만 `overflow-x: scroll`.

바텀시트를 함부로 쓰지 않는 이유도 토스가 측정했다:
> 화면 위에서 버튼을 누른 후 아래에서 올라오는 바텀시트의 버튼까지 시선이 닿으려면,
> 사용자들은 **인지 비용을 더 써야** 하기 때문에 선택까지의 시간이 늘어나게 돼요.
> — https://toss.tech/article/tds-component-making

또 하나 — **평균을 낼 때는 라벨을 바꾼다.** 원금균등상환에서 토스는 `원금 상환액`을
`평균 원금 상환액`으로 **relabel** 한다. 조용히 평균 내지 않는다.

### 4.2 용어 설명은 라벨 옆 `?` 아이콘 → 오버레이

DSR 계산기의 실제 구현: `icon-question-circle-mono`, 15px, grey600, `margin-left: 2px`.
누르면 **제목 + 한 문단 설명 + [닫기] 하나**짜리 오버레이.

```
기타 대출
기타대출에는 자동차대출, 카드대출, 학자금대출, 전세보증금 담보대출,
유가증권 담보대출 등이 포함됩니다.
                                                        [닫기]
```

우리 대상: 공정시장가액비율 · 과세표준 · 조정대상지역 · 1세대1주택 · 장기보유특별공제.

### 4.3 숫자 서식

`@toss/utils`가 오픈소스이고 **토스피드 프로덕션 번들과 구현이 일치**한다
(https://github.com/toss/slash/blob/main/packages/common/utils/src/Numbers.ts).

```
formatToKRW(13209802)                        // '1,320만 9,802원'
formatToKRW(13209802, { floorUnit: 10000 })  // '1,320만원'
commaizeNumber(13209802)                     // '13,209,802'
```

**띄어쓰기 규칙이 명문화돼 있다:**
> `shouldHaveSpaceBeforeWon` — 원 앞에 공백이 들어갑니다. **단독으로 금액을 표시할 때** true.
> (**문장 안에서는** 숫자와 원을 붙여 씁니다.)

```
단독 표시    1,320만 9,802 원
문장 안      … 9,802원을 내야 해요
```

⚠️ **만/억 축약은 전역 규칙이 아니다.** DSR 계산기는 만/억, 대출 계산기는 `12,345,678원`
그대로다. tossincome.com은 `6,500억원`·`3,000,000건`·`214,000원`을 섞어 쓴다.
**세액은 전액 표기를 기본으로 한다** — 1원 단위가 골든 케이스의 검증 단위이기 때문이다.

⚠️ **빨강/파랑 상승·하락 규칙은 1차 자료를 못 찾았다. 미확인.** 확인된 건 하나뿐 —
*"별로 위급한 상황이 아닌데 빨간색을 써서 실제보다 더 심각한 상황처럼 전달"*하지 말 것.
**세액이 늘어난다고 빨간색을 쓰지 않는다.**

### 4.4 절대금액 > 퍼센트

> 배달앱을 켜서 치킨을 고르고 있는 상황이라면, **30% 할인이라는 말보다는 치킨 5000원 할인이
> 더 와닿을 수 있어요.**
> — https://toss.tech/article/value-first-cost-later

```
❌  개편안 적용 시 24% 증가
✅  개편안 적용 시 320만 원 더 내요
```

관련 A/B (https://toss.tech/article/Marketing_Writing): `최대 100만 원`이 `최소 100원`에 졌고,
`미션` → `미션 4개`로 전환 4배, `빈칸 채우고` → `8칸 채우고`로 CTR 2배.
> 핵심은 **"얼만큼 해야 하지?" 하고 멈칫하는 순간을 없애는** 거예요.

## 5. 면책과 기준 표시

### 5.1 세 자리에 나눠 넣는다

토스 계산기의 실제 구조:

**① 결과 카드 안** (작게, `opacity: .7`, 11px)
```
* 제공하는 정보는 사용자가 직접 입력한 정보를 바탕으로 한 예측값이므로,
  실제와 다를 수 있습니다. 참고용으로만 사용해 주세요.
✱ 준법감시인 심의 완료 (2025-339호)
```

**② 입력 옆 마이크로 캐비엇** — 그 입력에만 걸리는 단서를 바로 옆에
```
* 마이너스대출은 빌린 금액이 아닌 한도금액 … 전체를 더해요.
```

**③ 화면 맨 아래 `유의사항`** — 접지 않고 **항상 노출**, 12px 회색, `line-height: 1.6`

### 5.2 우리 유의사항 초안

토스 문구를 우리 맥락으로 옮긴 것. **`-습니다`체를 쓴다** — 토스도 여기만 격식체다.

```

공개된 계산 방법으로 산출한 결과를 제공하는 서비스입니다.

2027년 이후 수치는 2026년 세제개편안(정부안)을 기준으로 한 예측값입니다.
개편안은 국회 통과 전이므로 심의 과정에서 달라질 수 있습니다.

계산 결과는 사용자가 입력한 정보에 기초한 예측값이므로 실제 부과 세액과 다를 수
```

## 6. 결과를 먼저 보여준다 (+67%)

토스 `내 보험`은 외부 기관 소관이라 검증 퍼널을 줄일 수 없었다. 대신 **더미 데이터로 결과

> 이 화면을 넣었더니, 조회를 끝내는 사용자 비율이 기존보다 **67%나 높아졌어요.**

우리 조건 화면은 §2.4의 세 기준을 모두 넘기므로 **이 처방이 그대로 적용된다.**

⚠️ **더미 데이터를 개인화하지 않는다.** 토스 시니어 조사에서 사용자가 예시 데이터를

## 7. 시니어 사용자 — 다섯 가지 실패

출처: https://toss.tech/article/senior-usability-research (토스 50+ 사용자 약 730만 명 대상)

1. **컴포넌트** — 텍스트와 `>` 꺾쇠를 누를 수 있는 것으로 인식하지 못한다. 태그를 버튼으로 오인
2. **예시 이미지** — 더미 데이터를 자기 것으로 읽는다
3. **모션 그래픽** — 안내를 읽지 않고 데모 동작을 흉내 내다 실패한다
4. **라이팅** — 질문형 텍스트의 주체를 오해한다 (§1.2)
5. **화면 구조** — **막연히 스크롤하지 않는다.** 접힌 곳 아래 내용은 없는 것과 같다

> 20~40대는 완벽히 이해되지 않아도 기존의 경험을 바탕으로 상황을 해결하는 경우가 상대적으로
> 더 많은 반면, **시니어는 이해되지 않은 제품을 의도대로 사용하기 어려운 경우가 많아요.**

**부동산 보유세 사용자는 토스 핵심층보다 나이대가 높다.** 5번 때문에 §4.1의 "펼쳐보기"를
쓸 때는 **닫힌 상태에서도 안에 무엇이 있는지 알 수 있게** 라벨을 써야 한다.

## 8. 따라 하지 말 것

- **토스 지표를 우리 근거로 삼지 않는다.** 보험청구 글은 같은 개선의 이탈 감소를 50%와 60%로
  다르게 적고, 추천 A/B 글의 저자는 *"실험의 변수가 잘 통제되어있진 않았어요"*라고 밝힌다.
  **가설을 가져오고 효과는 우리가 다시 잰다.**
- **마이데이터 전제 패턴.** "가입된 보험사만 보여주기" 같은 건 연동이 있어야 성립한다.
  다만 우리는 지도·공시가격 연혁이 있어 **같은 효과를 다른 방식으로** 낼 수 있다 —
  공시가격·조정대상지역·전년도 세액을 묻지 않는 것이 우리 버전이다.
- **역순 스택 회원가입 같은 신규 인터랙션.** 시니어 UT를 대량으로 돌린 결과이지 일반 규칙이 아니다.
- **해요체가 주는 안정감의 일부는 토스 브랜드에서 온다** (추정). 실제로 8원칙 글 댓글에는
  "판교 사투리"라는 비판이 여러 건 달려 있다.
